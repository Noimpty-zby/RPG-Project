# Aincrad：百层远征

一个 C++17 中文终端回合制 RPG。选择战士、法师或刺客，在十个章节中规划路线、培养技能、获取装备，并应对会根据行动改变意图的敌人。

本仓库保留游戏源码、构建配置、游戏测试和 CI。编译输出、编辑器缓存及个人存档不纳入版本控制。

## 快速开始

需要支持 C++17 的编译器。完整测试另外需要 Python 3；游戏本身没有第三方运行库依赖。

### CMake

```sh
cmake -S . -B build -DBUILD_TESTING=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
```

Linux/macOS 单配置构建运行 `./build/RPG_Game`。Windows Visual Studio 多配置构建运行 `build\Release\RPG_Game.exe`，建议使用 UTF-8 终端。MSVC 的源文件编码由构建配置设为 UTF-8。

### GCC / Linux / WSL

```sh
bash tools/test.sh
./build-local/RPG_Game
```

Windows PowerShell 使用 WSL 时：

```powershell
wsl -d Ubuntu-22.04 -- bash tools/test.sh
wsl -d Ubuntu-22.04 -- ./build-local/RPG_Game
```

脚本会编译游戏、运行核心测试及终端回归，并生成两份模拟 CSV。输出位于已忽略的 `build-local/`。

## 怎么玩

新游戏依次选择名字、职业、种子和挑战模式。每章选择一次路线，章内不能反复切换。

- **破坏线**：完成本章第 2、7 层，削弱本章 Boss 的核心压力并移除其护盾。
- **救援线**：完成 3 个非 Boss 楼层即可领取本职业装备订单；其他路线需要完成 5 个。
- **补给线**：首通本章第 3、7 层额外获得药水。

主菜单提供战斗、背包、装备、存档、状态、技能、营地和进入下一层。完成当前目标后才可前进。已通过楼层可以补练，但重复收益逐次降低，不能重复获得首通材料、订单或事件奖励。

十章依次为荒野前哨、幽林回廊、沉没书库、赤砂矿井、寒霜关隘、熔炉要塞、镜影剧场、星蚀观测站、王庭废墟和天顶之门。章节共享战斗引擎，拥有主题、Boss 配置、路线与持续生效的事件选择。

每章从第 5 层起提供一次事件。三类事件随章节轮换，金币成本随章节提高；选择前显示完整代价和后续效果。

| 事件 | 支付金币 | 接受代价 |
|---|---|---|
| 援助 | 本章商店九折、Boss 攻击降低 10% | 损失当前生命的 15%（不会致死），获得 3 材料 |
| 净化 | 移除本章敌人的剧毒词缀 | 消耗魔力恢复少量基础生命并获得 1 材料；魔力不足时改为少量非致死损血，无治疗 |
| 情报 | 本章敌人闪避降低 10 个百分点 | 获得金币，但本章 Boss 攻击提高 10% |

### 战斗目标与意图

遭遇包含击败敌人、生存、打断仪式和撤离。界面显示当前目标、进度与回合限制；击败敌人也可完成非击杀目标。目标遭遇中的守卫更耐打，玩家可以利用目标条件结束战斗，无须耗尽其生命。

第 1 章的特殊目标位于第 3、6、8 层，之后每章轮换位置与目标类型，路线也会影响目标；每章第 10 层始终为 Boss 战。

- 蓄力：普攻实际命中可以打断，随后出现休整窗口；未打断会转为可格挡的重击。
- 重伤：当前行动治疗效果降低，下一回合是否继续由敌人意图明确显示。
- 破防：格挡减伤失效，但仍恢复职业资源；攻击、削弱敌人也是可选应对。
- 读招：显示预测行动，改变行动可降低受到的伤害。

敌人根据近期治疗、格挡、出招历史、自身生命和特殊行动冷却作出选择。所有职业都有普攻、格挡和药水这些基础应对手段。无效输入、取消技能、使用失败不会重复回蓝、减冷却或推进回合。

普通击败目标最多 80 回合；打断目标最多 20 回合；撤离目标最多 15 回合。达到上限属于明确失败，会返回营地，不会无限循环。死亡优先于同回合击杀或目标完成。

### 成长和专精

五个基础技能分别在第 1、3、6、10、15 层开放，同时要求角色达到 1、2、4、6、9 级。技能阶数上限在第 20、40、65、85 层提升，最高 5 阶。角色正常成长上限为 100 级。

每职业前两个技能分别在第 10、30 层开放互斥专精，共 12 个分支：

| 职业 | 第一个技能 | 第二个技能 | 职业资源 |
|---|---|---|---|
| 战士 | 反击 / 重斩 | 坚守 / 振奋 | 战意：命中普攻或格挡积累，支持反击爆发 |
| 法师 | 蓄焰 / 火花 | 深冻 / 碎冰 | 专注：在恢复、控制和爆发之间安排回合 |
| 刺客 | 开隙 / 穿甲 | 伏击 / 扰乱 | 破绽：积累后爆发，或改用穿盾与干扰 |

每个技能只装一个分支。界面显示倍率、资源收益和代价。初选免费，重选费用为 `100 + 最高楼层 × 5`；只能在战斗外调整，并保留剩余冷却。升级技能也不能清空冷却。

技能基础成长采用线性加值，不再将技能等级重复乘入伤害。升级角色恢复基础生命的 12% 和最大魔力的 20%，不再回满。百分比恢复以不含护甲的基础生命计算，避免护甲同时无限放大血量和回血。

### 装备、保底与经济

保留武器、防具两个装备槽。品质为普通、精良、稀有、史诗；品质逐阶段开放。同层品质数值中心相差 15%，品质内浮动约 ±3%；稀有及史诗附带一个适用的功能效果。

功能效果包含普攻回蓝、格挡回蓝、技能节能和控制强化。营地可用材料替换一个效果，费用为 `3 + 品质序号 × 2`。材料不用于无限叠加攻击。武器、防具每个有效遭遇统一消耗 1 点耐久，使用技能不会绕过武器磨损。

随机首通掉落率为 60%，装备掉落倾向当前职业；选择武器或防具作为保底目标，分别最多经过 6 / 8 次未命中目标的首通即可获得可用目标装备。保底保证职业、部位和可装备等级，**不保证一定优于现有装备**。切换目标会清空进度；重复刷层不推进保底。

订单提供另一条确定的装备获取渠道。背包支持属性对比、锁定、按数量售卖和批量拆解；锁定装备、药水及已穿戴装备不会被批量拆除。材料已满时不会为了拆解而删除装备。

章节商店的库存、已购买位置和刷新次数会保存。跨菜单、跨本章楼层或读档不会免费刷新库存。刷新费用随章节及章内刷新次数增加，每章最多刷新 20 次。章节休息每章一次，费用与恢复量在菜单中说明。

### 失败、重玩与存档

失败后显示承伤、毒伤、被抑制的治疗、读招惩罚、打断和药水使用情况。复苏后回到当前楼层营地，可以调整专精、装备和补给；首通记录、路线和一次性奖励不重置。

提供标准、补给匮乏和无复苏模式；两种挑战模式的特殊敌人行动更频繁。种子保存在存档中，遭遇与商店分别派生随机序列，查看菜单不会影响下一场战斗。同一运行环境下，同种子及同样选择可复现；不同系统的 C 标准库随机实现不保证结果相同。

默认存档是运行目录下的 `save.dat`，仅战斗外保存。新建游戏直到主动保存才覆盖旧档；输入结束不会自动改写存档。

- 新格式为 **VERSION 3**，保存章节路线、事件、订单、商店、保底、统计、物品品质/效果/锁定、专精及冷却。
- 支持读取 VERSION 1/2。旧属性与超额技能阶数保留并显示传统存档标记；战斗仍使用新版公式，有效技能阶数封顶 5。
- 营地提供显式迁移：按进度规范等级和技能、保留装备及楼层，超额成长补偿最多 30 材料。迁移前建议另存备份。
- 存档先验证完整数据，再写临时文件并替换。失败保留原档；Windows 替换失败时尝试回滚，若回滚也失败会打印保留旧档的备份路径。
- 损坏字段、非法范围、重复记录、不兼容装备、非法专精及矛盾楼层记录会整档拒绝，调用方楼层保持不变。旧存档内容不会自动进行字符编码转换。

## 测试与结果解释

```sh
bash tools/test.sh
SANITIZE=1 bash tools/test.sh
SANITIZE=address bash tools/test.sh
```

第二条使用 UndefinedBehaviorSanitizer，并在首次发现未定义行为时终止；第三条同时启用 AddressSanitizer 与 UBSan，检查内存及未定义行为。七组核心测试覆盖成长、专精、敌人、战斗、掉落、存档和章节；Python 冒烟测试覆盖三职业真实终端、新建/读档、菜单取消、异常整数、EOF、旧档保留和死亡存档恢复。

- `balance_sim`：默认 4,800 场代表性独立遭遇。角色满资源、具备对应装备与已资助技能，用于局部对照，不能当作百层通关率。
- `campaign_sim`：216 次连续远征，包含 3 职业 × 4 种子 × 3 路线 × 3 模式 × 2 策略。等级、金币、药水、装备和耐久从第一层连续结算，不会在每层补满；失败最多重试两次，复苏遵守实际费用和模式。
- CSV 记录结束楼层、等级、金币、回合、全部药水消耗、死亡、装备改善机会、装备空窗、目标超时及非击杀目标完成次数。
- 固定策略与意图策略均是公开的简单规则，不是最优玩家。随机闪避、为保命错过打断窗口等情况可能达到明确的回合上限，包括标准模式的意图策略；这被记录为可重试的失败，不是引擎卡死。
- 自动门槛检查数据范围、每场回合上限、非击杀目标可完成，以及标准意图策略下每职业至少存在完整百层通关。**这些检查不能证明所有流派等强，也不能替代真人对节奏和重复感的试玩。**

2026-10-10 的 WSL Ubuntu 22.04 / GCC 11.4 回归中，标准模式样本结果如下。每格为 12 组种子/路线中的完整通关数；允许使用药水和按规则复苏，不能解释为零复苏通关率。

| 职业 | 固定策略 | 意图策略 | 意图策略平均药水 / 阵亡 |
|---|---|---|---|
| 战士 | 12/12 | 11/12 | 49.1 / 4.1 |
| 法师 | 7/12 | 7/12 | 51.5 / 5.8 |
| 刺客 | 9/12 | 9/12 | 53.3 / 5.3 |

读取意图的简单策略并不保证更高胜率；当前样本中三职业的药水与阵亡均减少，但战士有一组未通关。后续平衡应扩大种子和策略覆盖，并结合真人试玩，不应只为了让这一组脚本全胜而修改难度。

GitHub Actions 配置 Linux/Windows 的 CMake 回归，以及 Linux UBSan 检查。以 Actions 实际结果为准。

## 代码结构

```text
main.cpp                  终端菜单与输入
campaign.h/.cpp           十章路线、事件、营地、商店、统一结算
run_state.h               可持久化的远征状态
combat.h/.cpp             共享回合引擎、目标与战斗报告
world.h/.cpp              敌人数值、装备生成、掉落保底
progression.h             技能及品质阶段
game_config.h             公共边界、章节成本与重复收益
character/                基础角色
player/                   三职业、技能、专精、背包与装备
enemy/                    敌人词缀、条件意图、Boss 配置
item/                     物品 ID、品质、效果与锁定
save.h/.cpp               V1/V2 兼容与 V3 持久化
tests/                    回归、终端冒烟与两种模拟
tools/test.sh             独立于 CMake 的构建验证入口
.github/workflows/        游戏构建与回归 CI
```

调整成长从 `progression.h` 和 `player/skills.cpp` 入手；调整经济/敌人与掉落从 `game_config.h`、`world.cpp` 入手；调整章节从 `campaign.cpp` 入手。增加持久状态时，必须同步更新 `run_state.h`、`save.cpp` 和保存/读取回归。
