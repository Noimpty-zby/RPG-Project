# Aincrad：百层远征

一个 C++17 中文终端回合制 RPG。选择战士、法师或刺客，在十个章节中规划路线、培养技能、获取装备，并应对会根据行动改变意图的敌人。敌人图鉴、成就和远征记录跨局保留，游戏内有完整的帮助说明。

本仓库保留游戏源码、构建配置、游戏测试和 CI。编译输出、编辑器缓存、个人存档及档案不纳入版本控制。

除了终端版，`web/` 里还有一个可视化的浏览器版本：俯视探索楼层、横版回合战斗、像素美术与技能特效，规则与 C++ 版逐位一致，可以直接部署到 GitHub Pages。见下方「网页版」。

## 快速开始

需要支持 C++17 的编译器。完整测试另外需要 Python 3；游戏本身没有第三方运行库依赖。

### CMake

```sh
cmake -S . -B build -DBUILD_TESTING=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
```

Linux/macOS 单配置构建运行 `./build/RPG_Game`。Windows Visual Studio 多配置构建运行 `build\Release\RPG_Game.exe`，建议使用 UTF-8 终端。MSVC 的源文件编码由构建配置设为 UTF-8。

### GCC / Linux / WSL

```sh
bash tools/test.sh
./build-local/RPG_Game
```

Windows PowerShell 使用 WSL 时：

```powershell
wsl -d Ubuntu-22.04 -- bash tools/test.sh
wsl -d Ubuntu-22.04 -- ./build-local/RPG_Game
```

脚本会编译游戏、运行核心测试及终端回归，并生成两份模拟 CSV。输出位于已忽略的 `build-local/`。

## 网页版

`web/` 是同一款游戏的可视化版本，纯 HTML/CSS/JavaScript（ES 模块），不需要构建步骤，也没有第三方依赖：

- **地图**：每层按章节主题生成俯视地图（十章各有地块、墙面、装饰、氛围粒子，部分章节有光照）。入口有传送石（回访楼层、存档）、营火（休息、订单、保底、强化、修理、改造、专精）、商人；第 5 层起会遇到章节同伴（事件）；守卫站在封印的楼梯前，首通后楼梯解封，战利品留在宝箱里。
- **战斗**：横版回合制。敌人头顶显示意图，指令栏用数字键 1–5（普攻、技能、格挡、药水、查看）；15 个技能各有特效，另有打击顿帧、震屏、伤害数字、闪避、打断、Boss 双倍体型等表现。
- **美术与音效**：人物、50 种敌人、地块和图标全部由代码按调色板绘制（`web/js/engine/`），音效与音乐由 Web Audio 合成，没有图片或音频文件。
- **存档**：保存在浏览器 localStorage。营火旁的传送石或菜单里可以手动存档；每场战斗结算和换层时写入自动存档。远征档案（图鉴、成就、记录）跨存档保留。
- **操作**：方向键 / WASD 移动，空格 / Enter 交互，Esc 打开菜单；手机上显示虚拟方向键和交互键，战斗界面会按横竖屏调整布局。

### 本地运行

ES 模块需要通过 HTTP 加载，不能直接双击 `index.html`：

```sh
python3 -m http.server 8000 --directory web
# 打开 http://localhost:8000
```

`web/dev/gallery.html` 会列出所有人物、NPC 和敌人精灵，调整美术时可以直接查看。

### 规则一致性

`web/js/rules/` 是 `src/` 规则层的逐行移植（随机数、职业、技能、敌人意图、章节、掉落、结算），只把 `std::cout` 换成带结构化数据的事件，供战斗画面播放动画；画面用的随机数（地图布局、粒子）使用独立的生成器，不会影响规则的随机序列。因此同一个种子在网页版和终端版里生成相同的远征。

```sh
bash tools/web_test.sh
```

脚本编译 C++ 的 `campaign_sim`，再用 Node 运行 JS 移植版：PCG32 黄金序列、`random_tests` 的整局生成指纹，以及 1,296 次连续远征的 CSV 必须与 C++ 输出逐字节相同；另有 JSON 存档往返与校验、档案解析和成就测试。CI 的 `web-rules` 任务运行同一脚本。**修改 `src/` 的规则时，需要同步修改 `web/js/rules/` 中对应的文件，否则这项检查会失败。**

### 部署到 GitHub Pages

`.github/workflows/pages.yml` 在 `main` 分支相关文件变化时（或手动触发）先运行 `tools/web_test.sh`，再把 `web/`（不含测试）发布到 Pages。首次使用需要在仓库 Settings → Pages 中把 Source 设为 **GitHub Actions**。发布后的地址形如 `https://<用户名>.github.io/RPG-Project/`。默认的 `github-pages` 环境只允许默认分支部署；如果想在合并前从其他分支预览，需要在 Settings → Environments → github-pages 中添加该分支。

## 怎么玩

新游戏依次选择名字、职业、种子和挑战模式。每章选择一次路线，章内不能反复切换。

- **破坏线**：完成本章第 2、7 层，削弱本章 Boss 的核心压力并移除其护盾。
- **救援线**：完成 3 个非 Boss 楼层即可领取本职业装备订单；其他路线需要完成 5 个。
- **补给线**：首通本章第 3、7 层额外获得药水。

主菜单：

```text
[1] 挑战本层 [2] 背包 [3] 装备 [4] 退出 [5] 存档 [6] 状态 [7] 技能 [8] 营地 [9] 下一层
[10] 前往楼层 [11] 远征档案 [12] 帮助
```

完成当前目标后才可前进。「前往楼层」可以回到任何已到达的楼层补练，但重复收益逐次降低，不能重复获得首通材料、订单或事件奖励。「帮助」按主题解释流程、意图、目标、职业、装备、词缀和存档；第一次玩可以先看这里。

十章依次为荒野前哨、幽林回廊、沉没书库、赤砂矿井、寒霜关隘、熔炉要塞、镜影剧场、星蚀观测站、王庭废墟和天顶之门。章节共享战斗引擎，拥有主题、Boss 配置、路线与持续生效的事件选择。

每章从第 5 层起提供一次事件。三类事件随章节轮换，金币成本随章节提高；选择前显示完整代价和后续效果。

| 事件 | 支付金币 | 接受代价 |
|---|---|---|
| 援助 | 本章商店九折、Boss 攻击降低 10% | 损失当前生命的 15%（不会致死），获得 3 材料 |
| 净化 | 移除本章敌人的剧毒词缀 | 消耗魔力恢复少量基础生命并获得 1 材料；魔力不足时改为少量非致死损血，无治疗 |
| 情报 | 本章敌人闪避降低 10 个百分点 | 获得金币，但本章 Boss 攻击提高 10% |

### 战斗目标与意图

遭遇包含击败敌人、生存、打断仪式和撤离。界面显示当前目标、进度与回合限制；击败敌人也可完成非击杀目标。目标遭遇中的守卫更耐打，玩家可以利用目标条件结束战斗，无须耗尽其生命。

第 1 章的特殊目标位于第 3、6、8 层，之后每章轮换位置与目标类型，路线也会影响目标；每章第 10 层始终为 Boss 战。

每章还有一个**精英楼层**（第 6 或 7 层，避开目标楼层），章节日志和楼层标题会提前标出。精英至少带两个词缀，生命 ×1.7、攻击 ×1.15，更难缠（特殊意图更频繁，被打断后不休整）；首通必得一件本职业、本层最高品质档的装备（部位按营地设置的保底目标）和 2 材料，并清空保底计数。重复挑战不再发放精英奖励。

普通敌人的生命约为基础曲线的 160%、攻击约为 85%，一场普通战通常需要 4–5 回合，敌人的意图有机会真正出场。

特殊意图的设计原则是：**不应对就比普通攻击更痛，应对了就有好处**。

| 意图 | 不应对 | 应对方式 |
|---|---|---|
| 蓄力 → 重击 | 下回合重击 220%（Boss 250%），之后不休整 | 普攻即可打断（被闪避也算），敌人休整一回合；或格挡减半 |
| 压制治疗 | 本回合治疗只生效 50%，再受 100% 伤害 | 这回合不回血 |
| 破防 | 120% 伤害，无视格挡 | 主动进攻，或用减攻技能 |
| 预判连招 | 重复被预判的行动：175% | 换一种行动：75% |

数值集中在 `src/enemy/enemy.h` 的 `IntentTuning`，游戏内帮助页直接读取这些常量。精英和补给匮乏模式的敌人更难缠：特殊意图更频繁，被打断后不休整。带【治疗】词缀的敌人在蓄力完成时回复 4% 最大生命，打断蓄力即可阻止。

敌人根据近期治疗、格挡、出招历史、自身生命和特殊行动冷却作出选择。所有职业都有普攻、格挡和药水这些基础应对手段。无效输入、取消技能、使用失败不会重复回蓝、减冷却或推进回合。战斗中选 `[5] 查看敌我详情` 可以看到敌人的词缀说明、战术提示、自身装备和技能状态，不消耗回合。

普通击败目标最多 80 回合；打断目标最多 20 回合；撤离目标最多 15 回合。达到上限属于明确失败，会返回营地，不会无限循环。死亡优先于同回合击杀或目标完成。

### 职业

| 职业 | 初始 生命 / 攻击 / 魔力 / 暴击 | 每级成长 生命 / 攻击 / 魔力 | 特点 |
|---|---|---|---|
| 战士 | 200 / 18 / 24 / 8% | 20 / 3 / 3 | 生命最高；格挡回复 6 MP 并积累战意 |
| 法师 | 150 / 12 / 40 / 12% | 17 / 2 / 8 | 魔力最高，每回合回复 3 MP，普攻命中回复 8 MP |
| 刺客 | 150 / 15 / 25 / 20% | 15 / 3 / 4 | 暴击最高，鬼步 15% 闪避攻击（剧毒和爆炸无法闪避） |

### 成长和专精

五个基础技能分别在第 1、3、6、10、15 层开放，同时要求角色达到 1、2、4、6、9 级。技能阶数上限在第 20、40、65、85 层提升，最高 5 阶。角色正常成长上限为 100 级。

每职业前两个技能分别在第 10、30 层开放互斥专精，共 12 个分支：

| 职业 | 第一个技能 | 第二个技能 | 职业资源 |
|---|---|---|---|
| 战士 | 反击 / 重斩 | 坚守 / 振奋 | 战意：命中普攻或格挡积累，支持反击爆发 |
| 法师 | 蓄焰 / 火花 | 深冻 / 碎冰 | 专注：在恢复、控制和爆发之间安排回合 |
| 刺客 | 开隙 / 穿甲 | 伏击 / 扰乱 | 破绽：积累后爆发，或改用穿盾与干扰 |

每个技能只装一个分支。界面显示倍率、资源收益和代价。初选免费，重选费用为 `100 + 最高楼层 × 5`；只能在战斗外调整，并保留剩余冷却。升级技能也不能清空冷却。

技能基础成长采用线性加值，不再将技能等级重复乘入伤害。升级角色恢复基础生命的 12% 和最大魔力的 20%，不再回满。百分比恢复以不含护甲的基础生命计算，避免护甲同时无限放大血量和回血。

### 装备、保底与经济

保留武器、防具两个装备槽。品质为普通、精良、稀有、史诗；品质逐阶段开放。同层品质数值中心相差 15%，品质内浮动约 ±3%；稀有及史诗附带一个适用的功能效果。

功能效果包含普攻回蓝、格挡回蓝、技能节能和控制强化。营地可用材料替换一个效果，费用为 `3 + 品质序号 × 2`。材料不用于无限叠加攻击。武器、防具每个有效遭遇统一消耗 1 点耐久，使用技能不会绕过武器磨损。

随机首通掉落率为 60%，装备掉落倾向当前职业；选择武器或防具作为保底目标，分别最多经过 6 / 8 次未命中目标的首通即可获得可用目标装备。保底保证职业、部位和可装备等级，**不保证一定优于现有装备**。切换目标会清空进度；重复刷层不推进保底。

订单提供另一条确定的装备获取渠道。背包支持属性对比、锁定、按数量卖出（堆叠物品可以只卖一部分）和批量拆解；锁定装备、药水及已穿戴装备不会被卖出或批量拆除，锁定也不影响营地改造。材料已满时不会为了拆解而删除装备。

章节商店的库存、已购买位置和刷新次数会保存。跨菜单、跨本章楼层或读档不会免费刷新库存。刷新费用随章节及章内刷新次数增加，每章最多刷新 20 次。

营地里的三种金币用途：

- **强化**：已穿戴装备每级数值 +5%（按当前数值计算，向下取整、至少 +1），最高 +5；强化到 n 级的费用为 `价格 × n`。强化保留在装备上，换下再穿仍然有效。
- **修理**：把已穿戴装备的耐久恢复到上限，费用为 `缺失耐久 × max(1, 价格 × (品质序号 + 2) / 80)`。普通装备修理不如直接买新的，强化过的高品质装备才值得修。耐久剩 3 场以内时战斗结束会提醒。
- **休息**：每章最多 3 次，价格依次为基础费用的 1×、2×、3×；补给匮乏模式每章只能休息 1 次。

### 敌人、图鉴与成就

每章有 4 种主题普通敌人和 1 名 Boss，共 50 种，例如荒野前哨的「警钟哨兵」「荆棘野狼」。每种普通敌人对应一种招牌战术（蓄力、压制治疗、破防、读招），战斗开始时显示针对性的应对提示。

「远征档案」包含：

- **敌人图鉴**：按章节记录遭遇过的敌人、首遇楼层、遭遇与战胜次数，以及战术说明；未遭遇的显示为 `？？？`。
- **词缀图鉴**：记录遭遇过的 7 种词缀及其效果。
- **成就**：17 项，包括各阶段 Boss、挑战模式通关、无伤 / 零药水 / 残血击败 Boss、单场打断 3 次、专精、史诗装备、三路线、三职业、图鉴收集等。
- **远征记录**：最近 20 次已结束的远征（通关，或阵亡后不再复苏），以及各职业最佳成绩。只有在本次运行中发生的通关或阵亡才会记录，重复读取同一份存档不会重复记账。

这些数据保存在运行目录下的 `profile.dat`，与存档分开，新游戏不会清空。档案损坏时会被改名为 `profile.dat.broken` 后重新开始；来自更新版本的档案不会被改写。

### 失败、重玩与存档

失败后显示承伤、毒伤、被抑制的治疗、读招惩罚、打断和药水使用情况。复苏后回到当前楼层营地，可以调整专精、装备和补给；首通记录、路线和一次性奖励不重置。

提供三种模式：标准；补给匮乏（资源紧张，敌人更难缠）；无复苏（敌人强度同标准，但阵亡即结束）。种子保存在存档中，遭遇与商店分别派生随机序列，查看菜单不会影响下一场战斗。游戏使用自带的 PCG32 随机数生成器（`src/core/random.h`），不依赖 C 标准库的 `rand`，因此同种子及同样选择在任何系统上都生成相同的远征；`random_tests` 用固定的黄金值在 Linux 和 Windows 的 CI 上验证这一点。旧版本（使用 `std::rand`）的存档仍可读取，但同一种子的后续内容会与旧版本不同。

默认存档是运行目录下的 `save.dat`，仅战斗外保存。新建游戏直到主动保存才覆盖旧档；输入结束不会自动改写存档。档案 `profile.dat` 在每场战斗结束、解锁成就和远征结束时自动写入。

- 新格式为 **VERSION 4**，保存章节路线、事件、订单、商店、保底、统计、休息次数、物品品质/效果/锁定/耐久上限/强化等级、专精及冷却。
- 支持读取 VERSION 3：物品的耐久上限取当前耐久，强化等级为 0；保存后升级为 VERSION 4。
- 支持读取 VERSION 1/2。旧属性与超额技能阶数保留并显示传统存档标记；战斗仍使用新版公式，有效技能阶数封顶 5。
- 营地提供显式迁移：按进度规范等级和技能、保留装备及楼层，超额成长补偿最多 30 材料。迁移前建议另存备份。
- 存档先验证完整数据，再写临时文件并替换。失败保留原档；Windows 替换失败时尝试回滚，若回滚也失败会打印保留旧档的备份路径。
- 损坏字段、非法范围、重复记录、不兼容装备、非法专精及矛盾楼层记录会整档拒绝，调用方楼层保持不变。旧存档内容不会自动进行字符编码转换。

## 32 项改进与验证对照

下面记录具体落点，避免把“增加系统”当作已经验证了体验。体验与职业胜率仍应结合试玩和持续模拟调整。

| # | 问题 | 已实现的处理 | 主要验证 |
|---|---|---|---|
| 1 | 培养线性 | 技能互斥专精与装备功能效果 | build_tests |
| 2 | 全升满后无取舍 | 一技能一分支、一装备一效果槽 | build_tests |
| 3 | 基础技能过晚 | 前 15 层提供全部基础技能，后续分阶成长 | skill_progression_tests |

第二条使用 UndefinedBehaviorSanitizer，并在首次发现未定义行为时终止；第三条同时启用 AddressSanitizer 与 UBSan，检查内存及未定义行为。九组核心测试覆盖随机数（PCG32 黄金序列、无偏取值、整局生成指纹）、成长、专精、强化与修理、敌人、战斗、掉落、存档（含 V3 升级与 V4 新字段校验）、章节（含精英楼层、精英奖励和多次休息），以及档案（图鉴映射、成就条件、远征记录、损坏/新版本档案的处理和帮助页）；Python 冒烟测试覆盖三职业真实终端、新建/读档、菜单取消、异常整数、EOF、旧档保留、死亡存档恢复、帮助、远征档案、楼层回访、战斗中查看、部分卖出、营地强化/修理和远征记录不重复。

- `balance_sim`：默认 4,800 场代表性独立遭遇。角色满资源、具备对应装备与已资助技能，用于局部对照，不能当作百层通关率。
- `campaign_sim`：1,296 次连续远征，包含 3 职业 × 24 种子 × 3 路线 × 3 模式 × 2 策略（全部跑完约 1 秒）。等级、金币、药水、装备和耐久从第一层连续结算，不会在每层补满；失败最多重试两次，复苏遵守实际费用和模式。两种策略在 Boss 层前都会用金币把药水补到 4 瓶（必要时刷新商店，最多 5 次）；强化费用不超过手头金币四分之一时就强化已穿戴装备；耐久降到四分之一以下且负担得起时修理；生命低于 40% 时休息。意图策略会打断蓄力、避开被预判的行动、在压制治疗时不喝药，并在重击预计伤害达到当前生命 30% 时格挡（能一击击杀敌人时除外）；固定策略不看意图，按顺序出招。
- `campaign_sim --seeds N --report`：用 N 个种子输出标准模式的节奏报告——普通战平均回合与承伤、精英首战胜率与回合、强化/修理/休息的金币花费、结局金币，以及每个 Boss 的首战胜率表。
- CSV 记录结束楼层、等级、金币、回合、全部药水消耗、死亡、装备改善机会、装备空窗、目标超时及非击杀目标完成次数。
- 固定策略与意图策略均是公开的简单规则，不是最优玩家。随机闪避、为保命错过打断窗口等情况可能达到明确的回合上限，包括标准模式的意图策略；这被记录为可重试的失败，不是引擎卡死。
- 自动门槛检查数据范围、每场回合上限、非击杀目标可完成、标准意图策略下每职业至少存在完整百层通关，并且每职业至少一半的标准意图策略远征能完整通关（宽松的回归下限，不是平衡目标）。**这些检查不能证明所有流派等强，也不能替代真人对节奏和重复感的试玩。**

### 第四轮：让敌人意图真正重要

查补给匮乏模式"为什么不难"时发现了更根本的问题：敌人的特殊意图即使完全不应对，造成的伤害也比普通攻击少。"蓄力 → 重击 → 休整"三回合只造成 135–160%，而三次普通攻击是 300%。所以敌人放招越频繁，玩家越轻松，挑战模式靠"更常放招"加难度的方向是反的；把标准模式的放招频率提到挑战水平做实验，阵亡反而减少，连不看意图的固定策略都更容易通关。

调整内容：

- 招式伤害：重击 135%/160% → 220%/250%（普通/Boss），且重击后不再白送休整回合；压制治疗 80% → 100%；破防 80% → 120%；读招命中 150% → 175%（换招仍为 75%）。全部集中到 `IntentTuning`。
- "更难缠"的敌人（精英、补给匮乏模式）被打断后不再休整；无复苏模式不再提高放招频率，难度只来自单条命。
- 【治疗】词缀从"休整回合回血"改为"蓄力完成时回血，打断即可阻止"，否则打断反而会让它回血。
- 重新校准：Boss 攻击倍率 ×1.8 → ×1.7，精英攻击 ×1.25 → ×1.15，法师生命 140/+15 → 150/+17。模拟器的意图策略改为在重击预计伤害达到当前生命 30% 时格挡。

### 第三轮：跨平台一致的随机数

原来所有随机数都来自 C 标准库的 `std::rand`。它在 Linux（glibc）和 Windows（MSVC，`RAND_MAX` 只有 32767）上的算法不同，同一个种子在两个系统上会生成不同的远征，各平台 CI 的模拟结果也不可比。

- 新增 `src/core/random.h/.cpp`：PCG32 生成器加无取模偏差的 `below(n)`，替换全部 `rand()`/`srand()`。实现已用 PCG 官方参考输出核对。
- 新增 `random_tests`：固定种子的黄金序列、`below()` 的边界与分布，以及一个"整局生成指纹"（3 职业 × 2 种子的开局装备、全部 100 层敌人、10 个章节商店和首通掉落折算成一个哈希）。CI 在 Linux 和 Windows 上跑同一组黄金值，结果一致即证明跨平台一致；有意修改生成规则时，按失败信息里打印的新值更新常量。
- `campaign_sim` 默认种子从 8 个提高到 24 个。用 24 个种子复查时发现，第二轮"补给匮乏模式略难于标准模式"的结论落在 8 个种子的噪声里，并不成立，已在上文更正。

仍然保留一个由游戏自己管理的共享生成器（不再是 C 库的状态）。如果将来要彻底去掉共享状态，需要把生成器作为参数传给战斗、敌人和技能，改动较大，目前没有必要。

### 第一轮：平衡

用 24 个种子（原来只有 4 个）跑连续远征后发现，Boss 难度并不是平滑上升的：第 50、80、90 层的 Boss 首战胜率明显低于前后章节，法师在所有 Boss 上都落后。原因有两个：

1. 没有「蓄力」战术的 Boss（第 50、80、90 层）从不提供打断和休整窗口，每回合都在输出；
2. 第 1/4/7/10 章的「援助」事件能让 Boss 攻击降低 10%，而第 2/5/8 章的「净化」对 Boss 几乎没有作用，难度随事件类型来回摆动。

### 第一轮：修复

- 普通敌人名为英文（`Monster of Floor N`），且每次受击都打印 `...takes 48 damage, remaining HP:0`（英文、缺空格）。现在敌人有中文主题名，受击信息为中文。
- 刺客的「鬼步」会闪避剧毒和死亡爆炸伤害；现在这两类伤害无法闪避或格挡。
- 已锁定的装备穿上后无法改造，且提示不说明原因；锁定现在只防止卖出和拆解。
- 装备效果有三套不同的名字（如「格挡恢复/格挡回蓝」「施法节能/技能节能」）；现在统一为普攻回蓝、格挡回蓝、技能节能、控制强化，并在背包、装备、商店和改造界面显示完整说明。
- 状态界面的职业显示为英文（`Assassin`），日志里挑战模式显示为数字；现在均为中文。
- 满血时也会打印「HP 恢复 0」；无词缀敌人的 `[普通]` 与下一行粘在一起。
- 卖出、使用物品、升级技能失败时没有任何提示；现在会说明原因。卖出会显示获得的金币。

### 第一轮：新功能

- 游戏内帮助（主菜单 `[12]`），7 个主题。
- 50 种主题敌人、敌人图鉴与词缀图鉴、17 项成就、远征记录（主菜单 `[11]`，保存在 `profile.dat`）。
- 回到已到达的楼层补练（主菜单 `[10]`）。
- 背包可以只卖出堆叠的一部分。
- 战斗中 `[5] 查看敌我详情`；战斗中的技能列表改为紧凑格式，显示可用/冷却/未解锁/MP 不足。

### 第一轮：代码整理

- 职业改为 `Job` 枚举，基础属性与成长集中在 `jobProfile()` 一张表里，新角色、升级和传统存档迁移共用；删除了约 40 处 `getjob() == "Warrior"` 字符串比较和三份重复的升级代码。
- 修正拼写：`Affix::POSIONOUS` → `POISONOUS`，`dogeRate` → `dodgeRate`。
- 删除未使用的代码：技能的 7 个 setter、`skill::learnSkill(int)`、`Mageskill_4::canUse`、`SaveSystem::deleteSave`、英文的 `Character::attacktarget`；`dropItem` 改为可指定数量的 `sellItem`。
- 头文件不再 `using namespace std`；专精名称与说明集中到 `skills.cpp`；战斗伤害来源用 `DamageSource` 明确区分。
